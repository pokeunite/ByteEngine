MODULAR WEAPON GAMEPLAY 3 — EVENT-SHEET SETUP

Version 3 removes automatic animation playback and animation-name fields from Weapon Definition. There is no hidden equip/fire/reload animation trigger or playback-speed change in Weapon Instance.

Copy the two sample .byteevents assets into your project's Assets/Events folder.
Attach FPS controls to the player/equipment object. Turn off Weapon Equipment > Use Built In Fire Input so the sheet owns input.
Attach Weapon presentation to each weapon object, beside Weapon Instance and Animation Controller.
Create named animation actions Equip, Fire and Reload in each weapon's Animation Profile. Their clip selections and blending remain native profile settings.

Edit Weapon presentation to choose when animations play. The rules use the ordinary Animation > Play Named Action and Cancel Action actions. Removing/disabling a presentation rule stops that animation while the weapon still fires/reloads.

HIT DATA
Weapons > Weapon shot hit populates the current event context's Last Ray Hit. Target Self works on a weapon with Weapon Instance; you can also target an equipment object to read its equipped weapon.
Use Last Ray Hit as the target of native object, damage or VFX actions. Physics > Save Raycast Result stores point, normal, distance, object ID and hit/miss status in your sheet owner's variables.
The sample saves ShotHit, ShotObjectId, ShotPoint, ShotNormal and ShotDistance on the weapon. A miss clears the saved result.
Weapons > Use weapon shot result as Last Ray Hit retrieves an existing result without another raycast. Hit index 0 is the nearest actual pellet hit; higher indices select other pellet collisions. Out-of-range indices return no hit.
These are actual hitscan collisions, not the projectile camera-aim ray. Projectile impacts are not represented as hitscan results.

Weapon events are independent per observing condition and object. An input sheet firing after a presentation sheet is observed on the following update rather than losing the event.
Weapon Definition still controls damage, ammo, fire rate, trigger mode and reload duration. Match reload duration to the source clip, or explicitly control playback speed in the presentation sheet.

MIGRATION FROM VERSION 2
Add the presentation sheet before using version 3: previous component animation-name fields no longer drive animations. Copy the sample rules into existing custom event sheets if desired. Existing built-in fire input remains available, but do not enable it alongside a sheet's fire-input rule.

Weapon shot hit: tick Last Ray Hit - check object, then pick Self or a scene object in Hit object. The weapon/equipment picker selects the firing source. No separate Last Raycast Hit Object condition is needed. Unticked accepts any hit; shotguns match any pellet and publish that hit.

Menu organization: Plugins > Modular Weapon Gameplay > Weapon Equipment or Weapon Instance. Self is the object executing this sheet; the picker preview is not a fixed weapon binding.

VERSION 3.4 — EDITABLE WEAPON HUD
Weapon Equipment no longer writes to a hidden status label. Camera and weapon-root bindings use scene-object pickers. The old statusTextObjectId is retained only for reading old scenes and has no effect.

Attach the Weapon HUD sample sheet to the equipment/player alongside FPS controls. It updates separate native UI Text objects named HUD Weapon Name, HUD Magazine Ammo and HUD Reserve Ammo when weapon values change. HUD Reload State is shown while reloading. In a project, choose each target with the action's object picker. Edit the format and component references in Set Formatted Text. Select the individual UI Text objects to change font, size, colour, placement and other styling. The sheet changes content and visibility only.

Weapon Equipment exposes the selected weapon's name, slot, magazine ammo/capacity, reserve ammo/capacity, ammo cost, infinite reserve, can-fire/can-reload, reload remaining/progress, cooldown, damage, RPM, range, spread, pellet count and modes. Use component references in actions or Read weapon value into variable. That action accepts either a specific Weapon Instance or an equipment object, and can write to Self, Scene, Global or a chosen object's variable.

Weapon Definition remains the editable source for shot damage/rate/range/spread, magazine and reserve limits, ammo cost, shot/trigger/reload modes, reload timing, projectile settings and muzzle effects. Weapon Instance exposes current ammo and simulation state. Implementation sequence counters are hidden; use the named weapon event conditions instead.

Set Ammo, Add Reserve, tuning and effect actions now respect an explicitly chosen weapon even when another weapon is equipped. Existing animation presentation sheets remain independent from the HUD sheet.

VERSION 3.5 — INVENTORY AND PICKUPS
Weapon Equipment > Start With No Weapons starts empty. Otherwise each Weapon Instance > Start In Inventory chooses starting ownership. Starting Slot selects the initial weapon; if missing, another owned weapon is selected. Carry Limit is a total weapon count; zero means unlimited. Starting inventory obeys the limit, prioritising Starting Slot. One weapon per definition slot is supported. Slots remain definition slots, not positions in the carried list.

Place Weapon Pickup on a separate world mesh, outside the camera and weapon rig hierarchy. Pick its Weapon Rig from the Weapon Instance objects beneath Weapon Root. The world mesh is separate from first-person arms. Set Pickup Radius. Link one world pickup per rig, including starting weapons if they can be dropped. Pickups hide when carried; Drop equipped weapon restores the linked pickup in front of the player. Ammo survives dropping and collecting. Drop refuses with an event warning if no world pickup is linked. It does not silently delete the weapon. Dropping does not simulate throwing or floor physics.

Copy Weapon inventory.byteevents to the project and attach to the equipment object. E collects one nearest eligible pickup; G drops. Edit keys and conditions normally. The pickup action enforces distance, capacity, existing ownership and slot conflicts. Tick Use nearest eligible pickup, or untick it and choose a world object or Last Ray Hit after your raycast. Can pick up weapon checks the same rules. Carries weapon, Has an equipped weapon and Weapon inventory is full support UI and gameplay. Set weapon carry limit changes future pickup capacity; lowering it does not delete existing weapons.

Native mouse conditions are under Input / Mouse: Mouse Button Held, Pressed and Released. Choose Left, Right or Middle. Existing mouse event IDs are unchanged.

First-person Animation Controller now observes the nearest parent Character Controller, so camera-child weapon rigs receive the player's real movement speed and grounded state. The range uses native character.setMoveSpeed event actions: speed 3 normally, speed 6 while Shift is held. The existing profile threshold 4 distinguishes Walk and Run. Fire, equip and reload actions still override locomotion through the presentation sheet.
