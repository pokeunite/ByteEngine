Web performance verification

Wrap-up: the repeatable 40 FPS target is not achieved. The installed working build measured 37.95 FPS with 100 spiders. Earlier runs reached 41.40 and 43.48 FPS, but later repeats fell below target. The failed cache-budget experiment has been removed from source and installed runtimes. Further optimization was stopped at the user's wrap-up request.

The target is 100 active animated spiders with correct gameplay, controls and effects. Tests use real Chrome/WebGL hardware on this laptop, at 1280 × 720 native world resolution. No game has been uploaded.

Measured normal game loop

These runs include real elapsed simulation time, audio and the normal performance recorder. Each measured run follows 600 warm-up frames and records 1,200–2,400 rendering completions. Completion intervals measure renderer throughput; they are not an operating-system display scanout measurement. Run-to-run variance remains material. The controlled stress scene uses a fixed camera, an invulnerable stationary player and 100 pursuing/attacking spiders; it does not replace a full moving-player playtest.

Verified changes

  • Off-thread WebGL and UI rendering with a bounded two-frame queue. Frame data is copied from WASM before the next managed frame, packed in aligned owned buffers, transferred and reused within a 64 MiB pool.
  • Automatic main-thread fallback when worker graphics are unsupported or the capability probe fails, before transferring the canvases.
  • Per-draw shader variants: ordinary objects keep the fast shader even when an advanced material, water or an additive effect is visible.
  • AI decisions spread across frames without changing their average frequency or interrupting committed attacks.
  • Event instruction lookups retained until their membership/identities change; live list replacement, instruction edits, timers and reset behavior tested.
  • Visual-only changes no longer rebuild the collision query index. Actual collider, geometry and parent activity changes remain immediate.
  • Typed scene/component and model-hierarchy caches invalidate only for relevant membership changes; duplicate object identities, reparenting and unload behavior are covered by regressions.
  • The mounted content package releases its assembly buffer. Large audio remains in browser-managed media blobs instead of duplicated JavaScript buffers.
  • Actors share immutable skin weights, vertex groups and packed GPU influences. Pose matrices and deformation buffers remain independent. Live imported-weight edits and model unloading are tested.
  • Navigation-driven spiders can use query-only movement capsules. They remain detectable by movement, aiming and projectile queries. This is editable under Mining Operation → Enemy collision → Enemy Movement Queries Only; dynamic rigid bodies retain normal solver contacts.
  • Purple hunter attacks, backs off approximately 2.7 metres, pauses, then pursues again. The sequence remains editable in its AI asset.

Correctness checks

  • Aim and fire held together; releasing one mouse button independently; Escape pause/resume; three viewport sizes.
  • Visible muzzle particles verified by comparing framebuffer pixels with and without effect draws.
  • Ordinary, normal-mapped, heightfield, sand, water and additive effects compared against the universal shader: maximum channel error 0.
  • CPU/GPU animated positions and shadow positions agree within 0.00001; palette batching preserves exact rendered colours.
  • Projectile sweep hits, knockback, collider query visibility, editable solver-contact opt-in and dynamic-body contact preservation tested.
  • Worker render completions have their own measured trace timeline. Main-thread transfer time is identified separately, and asynchronous GPU timings are not treated as synchronous frame costs.
