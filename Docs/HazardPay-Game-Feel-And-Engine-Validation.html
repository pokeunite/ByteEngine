Game-feel update & engine validation

The ten selected feedback features are implemented. The Windows runtime is refreshed separately from web. The 100-spider test has not reached 40 FPS. Results below document the remaining limits rather than claiming the performance goal is complete.

Your selected changes

  • Hit confirmation

    A brief marker and soft cue only after actual enemy health loss. Dead targets, scenery and invulnerable targets do not count.

  • Kill confirmation

    Gold kill marker and a distinct short cue, driven by the real damage result.

  • Spider hit reaction

    Renderer-local flash and small body recoil; original material values are restored without changing shared materials.

  • Player danger

    Directional hurt indication and low-health emphasis; unknown directions use a subtle edge warning.

  • Rig danger

    Warns during a spider’s actual drill-targeting wind-up. No false rig warning when it targets a nearby defence.

  • Combat mix

    Machines and music duck briefly during combat feedback; saved audio settings remain unchanged.

  • Ammo pickup

    Shows the amount actually collected, rather than the bucket’s theoretical capacity.

  • Credit payout

    Short payout feedback and a visual count-up. Purchases still use the real balance immediately.

  • Round result

    Compact ore and rig-condition result instead of a large interruption.

  • Camera feedback

    Small, bounded presentation-only impulses with a saved Camera shake slider. Zero disables them; aiming and projectile direction stay unchanged.

Manual runtime rebuild

Run these from C:\Users\codex\ByteEngine, with the editor closed. The installed launcher points at the maintained source checkout. These commands rebuild runtimes; they do not export a game.

powershell -ep bypass -file .\Rebuild-ByteEngine-And-Refresh-Dist.ps1

# Web only, when you want the web runtime refreshed:
powershell -ep bypass -file .\Rebuild-ByteEngine-And-Refresh-Dist.ps1 -BrowserOnly

# Both Windows and web:
powershell -ep bypass -file .\Rebuild-ByteEngine-And-Refresh-Dist.ps1 -IncludeBrowser

# Check matching Windows editor/player identity:
powershell -ep bypass -file .\Rebuild-ByteEngine-And-Refresh-Dist.ps1 -VerifyOnly

The default preserves existing browser files and builds Windows only. The bundled player is made from the same compiled core as the editor. Explicit browser refresh synchronizes Dist and Debug/Release copies. A Windows plugin update intentionally leaves web gameplay stale until you request that refresh.

Engine changes accepted — and held back

  • Accepted object-reference destruction queues and cached camera lookup, including cache invalidation and active/enabled fallback.
  • Retained this checkout’s existing cached render ordering and physics bounds; replacing them with the older proposed code would lose useful work.
  • Integrated independent frustum tests into index-addressed worker results, then collect visible objects in the original order. Graphics submission remains on its owner thread.
  • Did not parallelize collider gathering: this checkout has mutable bounds/transform caches that are not safe for that worker loop.
  • Preserved fixed-step delta assignment. The proposed main-folder patch had removed it.
  • The main folder and this checkout have diverged. This is a selective integration, not a wholesale merge that discards newer AI/animation systems.
