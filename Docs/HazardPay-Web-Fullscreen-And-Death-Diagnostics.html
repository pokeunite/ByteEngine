Fullscreen and spider-death investigation

3 November 2026 · Local Chrome tests · Hazard Pay / ByteEngine

Result: the updated local test reached 59.6 FPS in fullscreen Auto. Native rendering averaged 31.4 FPS. The reported near-zero itch.io collapse was not reproduced under these controlled conditions, including with the published runtime. This is a measured improvement pass and diagnostic build, not proof that every reported failure is resolved.

What changed

  • GPU skin binding bounds are shared between compatible actors; bone poses remain independent. Tests check distinct poses, changed source vertices and unloaded meshes.
  • Spider death clips use private animated poses by default instead of retaining many unique crowd-cache poses. Living crowd animation sharing remains enabled. The complete death animation is preserved. Gameplay plugin version: 3.66.0.
  • Normal performance recording uses a lightweight pulse. Full object/component inventories and detailed timings remain available in Deep profile. Earlier diagnostic sampling itself reached over a second under pressure, so it could distort the slowdown being investigated.
  • No water render target is allocated until a water draw needs it. Fullscreen Fast UI is capped at 1920×1080, independently of world resolution. Explicit Native world resolution remains available. Auto can respond sooner to sustained GPU pressure.
  • Deaths, resize and fullscreen changes trigger bounded in-memory captures of the preceding 120 and following 120 frames (or up to 10 seconds after the event). Four completed incidents are retained, plus one pending incident; overlapping triggers share a capture. F8 downloads the report. These captures do not automatically upload or persist after closing the page.
  • Audio decode timing markers help distinguish first-use sound work from animation and rendering work.

Death isolation

A clean three-spider run measured 71.0 / 76.3 / 68.3 FPS in the three death windows; maximum intervals were 48.6 / 25.1 / 39.8 ms. Callbacks took 12.8 / 1.4 / 1.4 ms. A matching-size cached-pose ablation also ran smoothly, so caching alone does not explain the originally reported severe hitches.

The cached ablation allocated about 1.44 MB and 1.30 MB in its first two death callbacks, compared with 124 KB and 3.6 KB in the default path. Its maximum animation work was 8.3 / 7.3 / 5.9 ms versus 1.4 / 1.2 / 1.5 ms. Managed memory after the third death was about 604 MB versus 540 MB. These are sequential observations, not exclusive memory attribution.

The clean 30-spider default setup measured 39.0 / 55.1 / 48.5 FPS through three scripted death windows; the first maximum interval was 127 ms. A separate cached run changed viewport size and is excluded from direct comparison. Scripted deaths use Health.Kill and include death subscribers and corpses, but do not reproduce a projectile's lethal hit or the entire live combat sequence.
