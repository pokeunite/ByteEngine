Counter covers total managed allocations, including other managed threads. Timing varied substantially between captures, so this is not a reliable isolated FPS comparison or a 40 FPS guarantee.

What changed

  • Lighting capture uses bounded nearest-light insertion instead of allocating and sorting all scene lights. Internal snapshot buffers transfer ownership instead of being copied repeatedly. Public snapshot construction still copies its inputs.
  • Point-shadow selection no longer creates a chain of anonymous candidate objects and sorting iterators. Existing influence-distance, intensity and stable-order rules are preserved.
  • Combat audio uses direct loops and reusable cleanup lists instead of temporary voice/filter arrays and scene-wide LINQ searches. Footsteps and machine impacts select clips without temporary arrays.
  • Defence health bars are hidden while business menus or the pause menu are open.

Verification

178 native gameplay checks passed. Engine optimization regression suite passed. Lighting capture with 100 point lights measures 768 bytes/pass; regression threshold is 2,500 bytes/pass. Tests cover nearest-light order, tie handling, live properties, immutable snapshots, shadow selection and menu suppression.

Scope

Windows editor and matching player runtime refreshed. No game export. Browser runtime intentionally unchanged under the Windows-first workflow; refresh it explicitly before a future web export. Remaining allocations are not eliminated: rendering snapshots, gameplay UI strings and other systems still allocate.
